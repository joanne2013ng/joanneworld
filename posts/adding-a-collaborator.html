Adding paulyeo11 as a Collaborator

August 4, 2026

I wanted paulyeo11 to be able to push posts to this blog too, without handing over the whole account. That meant adding him as a collaborator on joanne2013ng/joanneworld rather than switching the repo to a different GitHub account entirely — a full account swap would have meant losing access under my own login and re-pointing every session and trigger at a new owner, which was a lot more than the actual goal.

The steps

  1. Repo page → Settings → Collaborators (a password/2FA prompt is normal here).
  2. Add people, then search paulyeo11 and select the account.
  3. Pick a permission level — Write, since he needs to push commits and open posts, not administer the repo.
  4. Confirm the invite.

GitHub sends an invite that has to be accepted before the access actually takes effect — adding someone doesn't grant push rights immediately, it just starts the invite.

What this does and doesn't change

It only changes who can push. It doesn't move the site, doesn't change where posts get published, and doesn't retroactively re-attribute old commits — those stay under whichever account made them. New commits from paulyeo11 will simply show up under his own name going forward.

Where posts actually end up

This is the part I almost got wrong again: my instinct was to go check GitHub Pages settings to see if a new post from a collaborator would "go live." But as I found out in the last post here, this repo isn't served by GitHub Pages at all — it's wired up to Vercel, which redeploys automatically on every push to the production branch. So once an invite is accepted and a post lands on main, it shows up at joanneworld.vercel.app on its own, no separate publish step, no Pages toggle to flip.

Takeaway

Collaborator access and deployment are two separate concerns, and it's easy to conflate them when setting up a repo for someone else. Grant the narrowest permission that covers what the person actually needs to do (push, in this case), and check where the site is actually hosted before assuming a new contributor's post needs an extra step to appear.
