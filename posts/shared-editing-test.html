Two Editors, One Site: My Wife and I Both Push to Joanne's World

August 5, 2026

This site carries Joanne's name, but it's never really been a one-person operation. Today I wanted to settle a question that had been sitting in the back of my mind since we started: can we both actually edit this thing and get changes live, or is "shared access" just a permission checkbox that looks fine until someone other than the owner tries to use it?

The test

Nothing fancy — I made a small, harmless edit of my own to about.html, tagged clearly as mine, and pushed it through the same pipeline Joanne's edits go through: a feature branch, a pull request, and a merge into the branch the site actually deploys from.

That last part turned out to be the interesting bit. I'd assumed the production branch was main, the GitHub default. It isn't. A quick look at the repo's branches and merged PR history showed the real deploy branch has a much less obvious name — a holdover from however the project was first wired up. Vercel doesn't care what a branch is called, only which one it's configured to watch, and that configuration lived somewhere I had to go check rather than assume.

What "shared access" actually meant here

Once I knew the right target branch, the rest was unremarkable in the best way:

  • My commit landed on my own branch, not directly on production — same rule Joanne's edits follow.
  • A pull request merged it into the deploy branch.
  • Vercel picked up the push and rebuilt automatically, no manual "deploy" step for either of us to remember.

In other words, the workflow doesn't distinguish between "Joanne's edit" and "Paul's edit" at any point — it just distinguishes between "on the deploy branch" and "not yet." That's exactly what shared access should look like: not a special case, just the same door opening for both of us.

One wrinkle worth naming

My test edit was an HTML comment, so it doesn't show up anywhere on the rendered page — it only proves the pipeline works, not that visitors can see it. Good enough for a plumbing check, but next time I touch the site I'll make it something visible, if only so Joanne can point at the live page and say "yep, that's the one you pushed."

Takeaway

The interesting risk with shared editing was never "will Claude Code let two people commit to a repo" — of course it will. It was whether both of our changes actually reach the same live site through the same path. They do, as long as you first confirm which branch is really wired to the deploy, since it won't always be the one you'd guess.
