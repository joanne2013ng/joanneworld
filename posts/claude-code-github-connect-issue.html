Why I Couldn't Connect Claude Code to My paulsworld GitHub Repo

August 4, 2026

I ran into a snag today trying to get Claude Code to work with a second GitHub repo, paulyeo11/paulsworld, from inside a session that was already set up against this blog's repo. It didn't work, and the reason turned out to be a straightforward platform limitation rather than a bug — so here's what happened and how I actually fixed it, in case it saves someone else the confusion.

The problem

My Claude Code session was already bound to joanne2013ng/joanneworld. When I asked it to also attach paulyeo11/paulsworld so I could work across both repos in one place, the request failed with an error along the lines of:

cross-tier adds are not supported: session already has repos from owner(s) [joanne2013ng]. Start a new session with the requested repo as the initial source, or add a repo from the same owner as the existing sources.

In other words, a single Claude Code session can only add extra repositories that belong to the same GitHub owner/organization as the one it started with. Since joanneworld is owned by joanne2013ng and paulsworld is owned by paulyeo11, that's a cross-owner ("cross-tier") request, and it's blocked.

A detour: the Connectors panel isn't it

My first instinct was to go digging through Settings → Connectors, thinking that's where repo access gets granted. It isn't. Connectors is for non-GitHub data sources like Google Drive — it has nothing to do with picking a repository for a session. The actual repo/source picker lives in the New session flow, not in Connectors, and it's easy to end up in the wrong panel if you're not sure where to look.

The actual fix

Since an existing session can't be retargeted across owners, the fix is to start a fresh session with the other repo selected as its initial source:

  1. From claude.ai/code, start a New session.
  2. In the source/repository picker, search for paulyeo11/paulsworld.
  3. If it doesn't show up, the Claude GitHub App likely isn't authorized for that owner yet — grant access from the repo picker's "configure GitHub access" link (an org admin may need to approve it), then search again.
  4. Pick a branch (or leave it on the default) and any environment settings, then create the session.

That new session clones paulsworld fresh and works with it independently. It's a separate session from the one tied to joanneworld — there's no single session that spans both repos when they belong to different owners.

Takeaway

If you manage repos under more than one GitHub account or org, plan on one Claude Code session per owner rather than expecting to mix and match repos freely inside one session. And if a repo isn't reachable, check GitHub App authorization before assuming something is broken.
